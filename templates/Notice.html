🚜 Dashboard Agricole — v15.6

Application web de suivi des interventions agricoles, couplée à Traccar (GPS) et enrichie d'un carnet de terrain, d'une carte de chantier RTK avec alertes automatiques, d'un assistant d'import Traccar, d'un cahier de fertilisation et d'un module analytique.

Prérequis d'installation

Matériel recommandé

  • Pour une utilisation en réseau : NAS Synology ou tout serveur Linux
  • Pour une utilisation monoposte : un PC linux ou windows
  • Accès réseau local et/ou internet pour Traccar et météo

Python

  • Python 3.9 ou supérieur
  • Vérifier l'installation : python3 --version

Dépendances Python

Installez les packages requis via votre terminal :

pip3 install flask requests openpyxl fpdf2
Package Usage
flask Serveur web de l'application
requests Communication avec l'API Traccar
openpyxl Export Excel (.xlsx)
fpdf2 Génération des rapports PDF (analytique, fertilisation)

Les modules suivants sont inclus par défaut dans la bibliothèque standard Python : sqlite3, json, re, threading, csv, io, os, time, secrets.

Traccar

  • Instance Traccar accessible en réseau (locale ou distante)
  • Version Traccar ≥ 5.0 vivement recommandée
  • Les appareils GPS doivent être préalablement déclarés dans Traccar
  • Les périmètres virtuels créées dans Traccar correspondent directement aux parcelles de l'exploitation.

Configuration

Option 1 — Via l'interface (Recommandé, nouveauté v12.0)

Ouvrir le dashboard → ⚙️ État système → section Paramétrage Traccar :

  • Renseignez l'URL du serveur, l'identifiant et le mot de passe utilisateur.
  • Cliquez sur 💾 Enregistrer — la configuration est appliquée immédiatement sans aucun redémarrage.
  • Cliquez sur 🔌 Tester pour vérifier instantanément la bonne liaison avec l'API.

Cette configuration est définitivement sauvegardée dans le fichier config.json et rechargée automatiquement à chaque démarrage du serveur.

Option 2 — Dans le code (Fallback / Secours)

Si le fichier config.json est absent, l'application utilise par défaut les valeurs codées en dur situées dans dashboard.py :

TRACCAR_URL      = "http://votre-traccar:8082/api"
TRACCAR_USER     = "votre@email.com"
TRACCAR_PASSWORD = "votre_mot_de_passe"
DAYS_BACK        = 7    # Période par défaut en jours affichée à l'écran
CACHE_DURATION   = 60   # Durée du cache Traccar en secondes

Lancement

⚠️ Toujours démarrer via run.py, jamais dashboard.py directement. Plusieurs blueprints font import dashboard pour accéder à son état partagé (config Traccar rechargeable à chaud, etc.) et le voir toujours à jour. Cela ne fonctionne que si dashboard est le nom sous lequel Python a chargé ce fichier — or lancer python3 dashboard.py directement le charge sous le nom __main__, ce qui déclenche une erreur d'import circulaire au démarrage.

Pour démarrer l'application directement :

python3 run.py

Ou utilisez les scripts fournis :

bash start.sh     # démarrage en arrière-plan, log dans app.log
bash restart.sh   # arrêt puis redémarrage

L'application est ensuite accessible via votre navigateur à l'adresse : http://[IP-du-serveur]:8080.

Connexion par défaut

  • Identifiant : admin
  • Mot de passe : défini automatiquement lors du premier lancement (haché et stocké dans le fichier généré password_override.txt — jamais en clair).

⚠️ Pour des raisons de sécurité, il est fortement recommandé de changer le mot de passe via l'onglet Système → Changer le mot de passe dès votre premier accès. Un bandeau d'avertissement s'affiche automatiquement en haut du dashboard tant que ce changement n'a pas été effectué.

Ce tableau de bord condensé affiche quatre indicateurs cliquables :

Depuis la v14.2, la recherche est également disponible dans le Carnet d'interventions (filtre par parcelle, véhicule, outil, type ou produit) et dans le catalogue produits (filtre par nom, AMM, culture ou cible).

Carnet Phyto et Interventions

Saisie depuis une détection automatique Traccar

  1. Sur une ligne d'événement du tableau principal, cliquez sur le bouton ✍️ (Saisir).
  2. Sélectionnez le type d'intervention (celui-ci est automatiquement déduit en fonction de l'outil attelé).
  3. Renseignez la surface — le champ se pré-remplit automatiquement avec la surface cultivée cadastrale si elle est paramétrée, sinon il reste vide.
  4. Ajoutez les produits utilisés à partir du catalogue (la dose conseillée se pré-remplit seule).
  5. Importez la météo automatiquement 🔄 — le système récupère les données météo historiques exactes au jour et à l'heure de l'intervention (et non du jour actuel).
  6. Validez en cliquant sur Sauvegarder.

💡 Le bouton Modifier (✏️) présent dans l'historique du carnet vous permet de corriger ou modifier a posteriori absolument toutes les interventions (qu'elles soient issues d'une détection GPS ou saisies à la main). Le bouton 🗺️ (nouveauté v14.2), présent sur chaque fiche liée à un véhicule GPS, ouvre directement la carte de chantier à la date et sur le véhicule concernés.

Saisie manuelle

Pour enregistrer les travaux agricoles réalisés sans l'aide du tracker GPS Traccar :

  1. Sélectionnez une ou plusieurs parcelles via les cases à cocher (un champ de recherche textuelle ainsi que des boutons de sélection globale "Tout/Aucun" sont à disposition).
  2. Renseignez la date/heure, le tracteur et l'outil employé. Le type de travaux est déduit seul par rapport à l'outil choisi.
  3. La surface se pré-remplit avec la surface cadastrale uniquement si une seule parcelle est cochée.
  4. Ajoutez les produits et lancez l'importation de la météo historique.
  5. Si vous cochez plusieurs parcelles d'un coup : le système génère intelligemment une intervention distincte pour chaque parcelle.
  6. Saisissez la durée du chantier (en minutes) : elle sera sauvegardée et exploitée pour calculer les rendements en ha/h du module analytique.

🌾 Rendement à la récolte (nouveauté v15.0)

Un champ "Rendement (t/ha)" apparaît automatiquement dans les deux formulaires de saisie (GPS et manuelle) dès que le type d'intervention sélectionné est "Récolte" — invisible pour les autres types, pour ne pas alourdir la saisie courante.

🗓️ Filtre par campagne (nouveauté v15.0)

Un sélecteur "Toutes les campagnes" / année précise permet de n'afficher, par défaut, que la campagne en cours (la plus récente) plutôt que l'historique complet — la campagne de chaque intervention est résolue automatiquement (même logique que le Bilan et la Fertilisation). Le choix d'une campagne précédente est conservé le temps de la session, y compris après une sauvegarde.

✂️ Distinction des sous-parcelles (nouveauté v15.0)

Quand une parcelle est scindée en plusieurs cultures (voir Sous-parcelles), chaque sous-parcelle obtient sa propre carte dans le Carnet plutôt qu'un historique mélangé, avec son nom affiché dans l'en-tête. Les interventions liées à une sous-parcelle portent également un badge ✂️ individuel.

Catalogue Produits

Permet d'ajouter ou modifier vos intrants et fournitures :

  • Phytosanitaire : Renseigner obligatoirement le numéro AMM, la dose homologuée, le Délai Avant Récolte (DAR) et le stade BBCH cible.
  • Engrais : Saisir précisément les teneurs pondérales en Azote (N) / Phosphore (P₂O₅) / Potasse (K₂O) (%). Ces chiffres débloquent les calculs automatiques d'unités du cahier de fertilisation.
  • Semences : Indiquer la dose conseillée pour les semis. Pour le maïs, les besoins "semis→floraison" et "semis→maturité" (en °C.jours, base 6-30) activent le suivi phénologique de la Synthèse de campagne pour cette variété.

📦 Stock produit (nouveauté v15.0)

Deux champs optionnels sur chaque produit : stock restant et seuil d'alerte. Dès que le stock passe sous le seuil, un badge d'alerte apparaît sur la fiche produit, et le compteur "Produit(s) en stock faible" du bloc "📌 Aujourd'hui" (dashboard principal) le signale, avec le détail par produit.

🔄 Nouvelle campagne (nouveauté v15.0)

Bloc dédié dans "Gérer parcelles" : remet le statut de toutes les parcelles à "⏳ En attente" pour démarrer une nouvelle saison, sans toucher aux identifiants, surfaces, ni à l'historique des interventions passées (toujours consultable dans le Carnet). Action protégée par une double confirmation (case à cocher + saisie du texte de confirmation), vu son caractère irréversible sur les statuts.

🗺️ Carte de Chantier (RTK)

Accessible via l'icône 🚜 de la barre d'actions, ou directement sur /chantier. Cette page reconstruit, à partir des positions GPS brutes remontées par Traccar, la surface réellement travaillée par chaque véhicule — avec la largeur exacte de l'outil, et non une simple trace GPS filiforme.

Prise en main

  1. Choisissez une date (flèches ◀▶ pour naviguer jour par jour, ou bouton 📅 pour revenir à aujourd'hui).
  2. Sélectionnez un ou plusieurs véhicules dans le menu déroulant (recherche intégrée, boutons Tout sélectionner/désélectionner).
  3. Cliquez sur 🔍 Charger. Les corridors travaillés, la couverture des parcelles et les alertes s'affichent automatiquement.

Fond de carte

Trois fonds sont disponibles via les boutons segmentés : 🛰️ Satellite, 🌿 NDVI et 🗺️ Plan (OpenStreetMap).

🌿 NDVI Sentinel-2 : affiche l'indice de végétation coloré (rouge = sol nu/stress, vert = végétation dense), calculé côté serveur à partir des bandes Sentinel-2. Nécessite un compte gratuit Copernicus Data Space Ecosystem (recommandé) ou Sentinel Hub classique : cliquez sur l'icône ⚙️ à côté du sélecteur de fond de carte pour saisir vos identifiants (Client ID / Client Secret), testés et enregistrés automatiquement. Un sélecteur de date avec navigation ◀◀/▶▶ (pas de 14 jours) permet de consulter l'historique NDVI à une date passée plutôt que seulement l'image la plus récente.

📊 Historique NDVI par parcelle (nouveauté v15.3)

Contrairement au fond de carte NDVI (une image à consulter visuellement), l'onglet 📈 Analyses permet de transformer le NDVI en une vraie donnée numérique suivie dans le temps. Sur chaque carte de couverture de parcelle, un bloc "📊 NDVI" propose :

  • Bouton "📸 Capturer" : calcule le NDVI moyen actuel de la parcelle (moyenne sur tout le contour, via l'API Statistics de Sentinel Hub/Copernicus — pas juste une lecture visuelle) et l'ajoute à l'historique. Capture déclenchée manuellement, sur une image bien dégagée à l'écran, plutôt qu'automatiquement en tâche de fond (évite de capturer une image trop nuageuse sans le savoir).
  • Sparkline (petite courbe) qui apparaît automatiquement dès qu'il y a au moins un point, avec la date et la valeur au survol de chaque point.
  • Si la parcelle a des sous-parcelles, un bloc NDVI distinct apparaît pour chacune, avec sa propre capture et son propre historique — un contour de sous-parcelle donne un NDVI moyen bien plus représentatif de sa culture que celui de toute la parcelle quand elle est scindée.
  • La sparkline superpose aussi, en traits verticaux violets, les stades phénologiques déjà atteints (semis, floraison...) quand la parcelle/sous-parcelle est suivie en phénologie — pratique pour repérer si une baisse de NDVI correspond à une sénescence normale de fin de cycle ou à un décrochage suspect en pleine croissance.

Recherche automatiquement jusqu'à 10 jours en arrière la dernière image exploitable si le jour exact est trop nuageux, et affiche la date réelle de l'image utilisée plutôt que la date demandée.

⚠️ Alertes automatiques

Une bannière apparaît en haut du panneau Stats dès qu'une anomalie est détectée :

  • Vitesse anormale pendant le travail — au-delà du seuil configuré (15 km/h par défaut), signe probable d'une mauvaise application/dose. Marqueurs rouges sur la carte.
  • Arrêt prolongé, outil engagé (nouveauté v14.2) — le véhicule reste quasi immobile (moins de 1 km/h) pendant plus de 5 minutes (seuil configurable) alors que l'outil est actif : bourrage, panne, ou oubli de relever l'outil pendant une pause. Marqueurs carrés orange sur la carte.
  • Couverture de parcelle insuffisante — en dessous du seuil configuré (85% par défaut), voir ci-dessous.

Les trois seuils sont modifiables dans config.json, section alerts (voir Notes techniques).

📊 Couverture des parcelles travaillées

Dès qu'un chantier est chargé, l'application détecte automatiquement quelles parcelles ont été travaillées (test géométrique : au moins un point d'un passage à l'intérieur de la géofence), puis affiche pour chacune : le taux de couverture (%), la surface totale, la surface non couverte, et matérialise les zones manquantes en rouge sur la carte.

Cette analyse est disponible dans l'onglet 📈 Analyses du panneau latéral (nouvelle organisation en onglets depuis la v14.2, plus lisible que l'ancien panneau unique) :

  • Mode journalier (par défaut) : couverture du seul jour chargé.
  • Mode cumulé (nouveauté v14.2) — cochez "Cumuler sur une période" pour vérifier qu'une parcelle a été intégralement couverte sur plusieurs jours, voire toute une campagne, plutôt que sur une seule journée.

🔴 Mode suivi live

Le bouton 🔴 Live de la barre d'outils recharge automatiquement le chantier toutes les 30 secondes — utile pour suivre un chantier en cours. Disponible uniquement pour la date du jour, avec au moins un véhicule sélectionné.

🔀 Comparaison de deux dates

Le bouton 🔀 Comparer 2 dates ouvre deux cartes côte à côte, chacune avec sa propre date, affichant les passages travaillés des mêmes véhicules sélectionnés et un résumé de stats (surface/distance/passages) par côté — pratique pour comparer un avant/après ou deux jours d'une même parcelle.

📈 Résumé de période (Excel)

Toujours dans l'onglet Analyses : génère un classeur Excel sur une période (boutons rapides "7 derniers jours / 30 derniers jours / Ce mois-ci" ou dates libres) avec deux feuilles : le détail journalier par véhicule, et un résumé agrégé (jours actifs, surface totale, distance totale, ha/jour actif, vitesse moyenne pondérée).

✍️ Saisie rapide d'intervention (nouveauté v15.0)

Depuis l'onglet 📈 Analyses, chaque carte de parcelle affiche un bouton "✍️ Saisir" qui ouvre une fenêtre pré-remplie automatiquement à partir de ce qui a été détecté sur la carte :

  • Véhicule : liste des véhicules ayant effectivement travaillé cette parcelle ce jour-là
  • Type d'intervention : déduit automatiquement de l'outil détecté
  • Surface : la surface réellement couverte par le GPS (ou celle de la sous-parcelle si l'intervention y est rattachée, voir Sous-parcelles)

Un avertissement apparaît si une intervention existe déjà pour ce couple véhicule/parcelle/date (mise à jour plutôt que doublon). Pour ajouter des produits phyto/engrais et le détail météo, on utilise ensuite "✏️ Modifier" depuis le Carnet.

📍 Points d'observation terrain (nouveauté v15.0)

Bouton "📍 Ajouter un point" dans la barre d'outils : un clic sur la carte ouvre une fenêtre pour noter une observation géolocalisée (adventices, maladie/ravageur, panne, zone humide, autre), avec une note libre et une date. Les points sont indépendants de la date chargée — ce sont des notes de terrain durables, toujours visibles quelle que soit la journée consultée sur la carte.

Dans l'onglet Couches, un champ de recherche filtre les points par catégorie, texte ou date, avec une liste de résultats cliquables pour recentrer la carte dessus.

🌾 Modèles d'intervention (nouveauté v15.0)

Dans les formulaires de saisie (GPS et manuelle), un modèle réutilisable peut être chargé ou enregistré : "📋 Charger un modèle" applique instantanément un type d'intervention et une liste de produits/doses déjà configurée (ex: "Fongicide standard maïs"), évitant de ressaisir les mêmes produits à chaque campagne. Un modèle créé depuis la saisie manuelle est aussi disponible depuis la saisie GPS, et inversement.

✂️ Sous-parcelles (nouveauté v15.0)

Une même parcelle Traccar peut être scindée, pour une campagne donnée, en plusieurs zones cultivées différemment (ex: la moitié en maïs, l'autre en tournesol) — sans jamais toucher à la géofence Traccar elle-même, qui reste la seule référence pour l'historique, la carte de chantier et le calcul de couverture GPS existants.

Créer une sous-parcelle

Sur la carte de chantier, bouton "✂️ Sous-parcelles" → choisir la parcelle concernée → "✏️ Dessiner" pour tracer le contour à la main (clic par clic, 3 points minimum, puis "✓ Terminer"), ou "📂 Importer un fichier" pour un contour déjà existant. Un formulaire demande ensuite le nom, la culture et le statut.

📅 La campagne se désigne toujours par son année de récolte, jamais par une plage à cheval sur deux années civiles : un blé semé en octobre 2025 et récolté en juillet 2026 appartient à la campagne 2026, exactement comme un maïs semé en mai 2026. Le champ propose une valeur par défaut cohérente selon la date affichée (à partir d'août, l'année suivante est proposée), mais reste modifiable à la main.

📂 Import KML / GeoJSON (nouveauté v15.3)

Bouton "📂 Importer un fichier" dans la fenêtre "✂️ Sous-parcelles" : sélectionnez un fichier .kml ou .geojson/.json exporté depuis QGIS, Google Earth, ou votre logiciel de guidage — le format est détecté automatiquement.

  • GeoJSON : FeatureCollection, Feature isolée, Polygon et MultiPolygon (chaque sous-polygone d'un MultiPolygon devient une sous-parcelle distincte). Le nom et la culture sont repris automatiquement si le fichier contient des propriétés nom/name ou culture.
  • KML : chaque <Placemark> devient une sous-parcelle, avec son nom repris s'il existe.

Une fenêtre d'aperçu liste tous les contours détectés (avec leur surface calculée automatiquement) : décochez ceux à ne pas importer, ajustez le nom ou la culture si besoin, choisissez la parcelle de rattachement et la campagne une seule fois pour tout le lot, puis validez.

Visualisation et modification du contour

Les sous-parcelles s'affichent en permanence sur la carte (couche togglable "Sous-parcelles" dans l'onglet Couches), colorées selon leur statut, avec une infobulle au survol. Pour ajuster un contour déjà créé : ouvrir sa fiche → "✏️ Modifier le contour sur la carte" → chaque sommet devient déplaçable à la souris, le polygone se redessine en direct. Double-clic sur un sommet pour le supprimer (3 points minimum conservés). "💾 Enregistrer" recalcule la surface automatiquement.

🌽 La phénologie (maïs et céréales) distingue également les sous-parcelles : deux sous-parcelles semées avec la même variété à des dates différentes sont désormais suivies séparément, chacune avec sa propre date de semis et ses propres stades. Le calcul météo utilise en priorité les coordonnées exactes de la sous-parcelle plutôt que le centre de toute la parcelle.

Utilisation dans la saisie d'intervention

Dès qu'une parcelle a des sous-parcelles définies, un sélecteur "✂️ Sous-parcelle" apparaît dans les formulaires de saisie (GPS, manuelle, saisie rapide sur la carte) — invisible sinon, pour ne rien changer aux parcelles non scindées. Choisir une sous-parcelle :

  • Pré-remplit la surface avec celle de la sous-parcelle (pas la surface cadastrale de toute la parcelle)
  • Rattache l'intervention à cette sous-parcelle pour tous les calculs qui en dépendent (voir ci-dessous)

Statut et avancement automatiques

Comme pour une parcelle classique, le statut d'une sous-parcelle se recalcule automatiquement à partir de sa dernière intervention qui lui est spécifiquement rattachée (pas celles de la parcelle entière). La Synthèse de campagne affiche alors une carte Kanban distincte par sous-parcelle plutôt qu'une seule carte ambiguë pour toute la parcelle.

Impact sur les calculs (Bilan, Fertilisation, IFT)

Une intervention rattachée à une sous-parcelle voit sa culture et sa campagne résolues directement depuis la sous-parcelle elle-même (déjà connues sans ambiguïté), plutôt que par proximité de date avec un semis quelconque sur toute la géofence. Ça évite qu'un apport d'engrais sur une sous-parcelle "maïs" ne se retrouve mélangé, à tort, avec les données d'une sous-parcelle "tournesol" voisine simplement parce que leurs dates sont proches. Le nom de la sous-parcelle apparaît systématiquement dans le Bilan, la Fertilisation, le Carnet et le Cahier de traçabilité pour bien distinguer chaque culture.

📊 Synthèse de campagne

Page dédiée (icône 📊 dans la barre d'action, ou /synthese), pensée comme le tableau de bord du matin : "où en suis-je sur l'ensemble de l'exploitation ?", sans avoir à recouper plusieurs écrans.

Météo

Conditions actuelles (température, vent, pluie) à la position du premier véhicule actif, complétées d'une prévision 3 jours (icône, températures min/max, vent, pluie) — utile pour anticiper une fenêtre de traitement favorable.

Indicateurs clés

  • Parcelles suivies : nombre total
  • Avancement moyen (pondéré surface) : moyenne du statut de chaque parcelle (⏳ En attente 10% → 🚜 Préparé 30% → 🌱 Semé 55% → 💧 Traité 80% → 🌾 Récolté 100%), pondérée par la surface de chaque parcelle — une parcelle de 50 ha pèse plus dans la moyenne qu'une de 2 ha.
  • Alertes actives : total combiné des alertes DAR, vitesse anormale et arrêts prolongés (ces deux dernières recalculées pour la journée en cours uniquement, sans cumul historique, pour rester rapide même avec beaucoup de véhicules)

Vue Kanban / Liste

Les parcelles s'affichent par défaut en colonnes par statut (vue Kanban), ou en liste triable (recherche, filtre par statut, tri par avancement ou par ancienneté d'intervention). Une parcelle avec une alerte active affiche un badge ⚠️ directement sur sa carte. Chaque parcelle est cliquable et ouvre la carte de chantier sur sa dernière intervention connue.

🌽🌾 Phénologie (maïs et céréales à paille)

Deux frises distinctes apparaissent automatiquement dès qu'au moins une parcelle est concernée :

  • Maïs : 11 stades (🌰 Semis → 🌱 Émergence → 🌿 3 feuilles → 🍃 5-6 feuilles → 🎋 10-12 feuilles → 🌾 Floraison mâle → 🎀 Floraison femelle → 🥛 Grain laiteux → 💎 Lentille vitreuse → ⚫ Maturité → 🌽 Récolte), calculés en cumul de degrés-jours base 6°C, plafond 30°C (méthode française standard) depuis le semis. Ne suit que les parcelles semées avec une variété dont les besoins semis→floraison / semis→maturité sont renseignés dans le catalogue produits (fiche semence).
  • Céréales à paille (blé, orge, avoine, triticale) : 10 stades communs, calculés en base 0°C sans plafond, sans saisie par variété (détection via le champ "Culture" de la semence). Seul le stade "Épi 1 cm" (~1000°C.j) est solidement sourcé (Arvalis) ; les autres sont des ordres de grandeur usuels.

Chaque stade affiche sa date : réelle si déjà atteint (retrouvée dans l'historique météo), ou estimée (préfixée ~) par extrapolation du rythme récent d'accumulation pour les stades à venir — une estimation, pas une prévision météo fiable.

🔍 Anomalies détectées

Section repliable qui signale automatiquement des incohérences de saisie à vérifier : chronologie suspecte (semis moins de 60 jours après une récolte sur la même parcelle), doublon probable (deux interventions identiques à moins de 2h d'écart, même véhicule), surface très différente de la surface cadastrale. Ce sont des signaux, pas des blocages.

📄 Export PDF

Bouton "📄 Export PDF" : vue d'ensemble, tableau complet des parcelles (statut, avancement, surface, dernière intervention), tableaux de phénologie (maïs et céréales, stade actuel + prochain stade daté) et liste des anomalies détectées.

🔗 Lien de partage en lecture seule

Depuis "⚙️ État système" (dashboard principal), un lien de partage peut être généré (libellé + durée de validité 1 à 90 jours) pour montrer l'état de la campagne à un tiers (conseiller, banquier...) sans lui donner accès au reste du compte. La vue partagée masque l'export PDF et les anomalies (données internes), et ne permet pas de naviguer vers la carte de chantier (réservée aux comptes connectés). Le lien est révocable à tout moment.

🔴 Mode Live

Rafraîchit la page automatiquement toutes les 60 secondes — pratique pour une page laissée ouverte en fond toute la journée. Le choix de vue (Kanban/Liste) et les filtres sont conservés d'un rafraîchissement à l'autre.

📔 Cahier de traçabilité

Export PDF simple et lisible, accessible depuis l'en-tête du Carnet (bouton "📔 Cahier de traçabilité"), ou directement sur /export_cahier_tracabilite. Contrairement au registre phyto réglementaire (XML/Excel, qui exclut les engrais), ce cahier couvre tous les types d'intervention et tous les produits — c'est un carnet de suivi général, pas un document de substitution réglementaire.

Contenu : page de garde (exploitation, période, date de génération), puis une section par parcelle — et par sous-parcelle quand la parcelle est scindée (voir Sous-parcelles) — avec chaque intervention présentée en fiche lisible (date, type, véhicule/outil, surface, produits avec dose et unité).

🛰️ Import Traccar

Accessible via l'icône 🛰️ de la barre d'actions, ou directement sur /traccar_import. Cet assistant permet de créer/lier en masse des véhicules et des parcelles sur votre serveur Traccar, sans passer par son interface d'administration native.

Connexion

  • L'URL et les identifiants Traccar déjà configurés dans le dashboard (voir Configuration) sont pré-remplis automatiquement à l'ouverture de la page.
  • Deux modes d'authentification : Token ou Email + mot de passe.
  • Bouton Tester la connexion pour vérifier la liaison avant de lancer un import.

🔧 Note technique : les requêtes vers Traccar transitent par un proxy côté serveur du dashboard plutôt que directement depuis le navigateur, pour contourner les restrictions CORS que la plupart des installations Traccar appliquent par défaut.

Import de véhicules

  • Saisie manuelle : ajoutez des lignes nom + plaque directement dans le formulaire.
  • Fichier CSV : colonnes attendues name/nom et plate/plaque (virgule ou point-virgule accepté). Un aperçu avec case à cocher par véhicule s'affiche avant l'import (nouveauté v14.2) — décochez les lignes à exclure.

Import de parcelles

  • Glissez un fichier GeoJSON ou KML exporté depuis votre boîtier de guidage (John Deere, Ag Leader...) ou un logiciel SIG.
  • Un aperçu affiche chaque polygone détecté avec case à cocher. Les sous-sections auto-générées par certains boîtiers (motifs du type "Section_12") sont décochées automatiquement, l'utilisateur choisit de les inclure ou non.

⚠️ Détection de conflits (nouveauté v14.2)

Dès que la connexion est établie, la page compare en arrière-plan les véhicules et parcelles chargés à ce qui existe déjà sur le serveur :

  • Véhicule : badge rouge "⚠️ conflit" si un véhicule du même nom existe déjà avec une plaque différente — signe possible d'une confusion à vérifier avant import.
  • Parcelle : badge informatif "ℹ️ déjà existante" si le nom existe déjà côté serveur — elle sera réutilisée, aucun doublon n'est créé, c'est purement informatif.

Liaisons véhicule ↔ parcelle (interactive depuis la v15.4)

La case "Assurer que tous les véhicules sont liés à toutes les parcelles" complète automatiquement la matrice complète véhicules × parcelles après l'import (dans les deux sens), peu importe ce qui a été ajouté dans la session en cours. Le bouton 🔗 Voir les liaisons actuelles affiche un tableau croisé de l'état réel sur le serveur.

(nouveauté v15.4) Ce tableau est désormais interactif : chaque cellule est cliquable pour lier (●) ou délier (✕) un véhicule existant et une parcelle existante, sans repasser par un import complet. La modification est appliquée immédiatement sur le serveur Traccar (création ou suppression de la permission correspondante), avec confirmation visuelle et journalisée dans le panneau de log en bas de page.

Gestion des parcelles

Le bouton 🗑️ Gérer les parcelles liste toutes les parcelles présentes sur le serveur Traccar avec possibilité de suppression directe (confirmation demandée, action irréversible).

🕘 Historique des imports (nouveauté v14.2)

Chaque import termine par un enregistrement automatique côté serveur (date, URL, nombre de créations/réutilisations/erreurs). Le bouton 🕘 Historique des imports affiche les 30 derniers imports — persistant côté serveur, donc consultable même en changeant de poste.

🌾 Importer des parcelles depuis le RPG (IGN) (nouveauté v15.5)

Le bouton 🌾 Importer depuis le RPG (IGN) ouvre une carte interactive permettant de créer des géofences Traccar directement à partir du Registre Parcellaire Graphique (parcelles PAC déclarées, IGN/ASP — Licence Ouverte, gratuit, sans clé), sans avoir à redessiner un contour à la main.

  • Recherche d'adresse pour se positionner rapidement sur la carte (service de géocodage de la Géoplateforme IGN).
  • Deux niveaux disponibles : Parcelles (une culture homogène, redessinée chaque campagne selon ce qui est semé — millésime au choix, à partir de 2015) ou Îlots (contour stable dans le temps, délimité par des éléments physiques — route, chemin, haie —, ne change généralement pas d'une campagne à l'autre, plus adapté à une géofence qui n'a pas vocation à être redessinée chaque année).
  • Après zoom sur le secteur voulu, le bouton 🌾 Afficher sur la carte dessine toutes les entités (parcelles ou îlots) de la zone visible.
  • Clic direct sur une parcelle/îlot affiché : une fenêtre s'ouvre avec sa surface, son code culture (pour les parcelles) et son identifiant ; il suffit de saisir un nom et de cliquer sur ➕ Créer la géofence pour l'ajouter au serveur Traccar.

⚠️ Le niveau Îlots n'est disponible que pour la dernière édition publiée du RPG (pas de sélection par millésime pour ce niveau) — les données proviennent d'un flux différent de celui des parcelles.

🌿 Intégration e-phy (ANSES)

Le dashboard est connecté à la base officielle e-phy de l'ANSES — le référentiel national des produits phytosanitaires autorisés en France. Les données sont issues du portail data.gouv.fr (Licence Ouverte), mises à jour chaque semaine.

Synchronisation

  • Automatique : Au démarrage du serveur, si la base locale a plus de 7 jours, une synchronisation est lancée en arrière-plan (~2 minutes, ~4 Mo téléchargés).
  • Manuelle : Via ⚙️ État système → bouton 🔄 Mettre à jour ou 📥 Télécharger.
  • La base locale contient environ 5 000 produits réellement autorisés (noms commerciaux principaux et secondaires confondus) et ~19 000 usages. La recherche est instantanée, même sans connexion internet.
  • (correctif v15.4) Les produits vendus sous plusieurs noms commerciaux pour un même numéro AMM (ex : un produit renommé au fil du temps) remontent désormais tous dans la recherche, y compris les anciens noms — auparavant seul le nom principal était indexé.

⚠️ Alertes Réglementaires

Le dashboard intègre trois alertes automatiques pour vous aider à rester en conformité réglementaire.

1. Dose vs Dose Homologuée (temps réel)

Dans la saisie d'une intervention, le champ dose change de couleur en fonction de la dose homologuée e-phy :

CouleurSignification
🟢 VertDose correcte (≤ 90% de la dose max)
🟡 OrangeDose élevée (entre 90% et 100% de la dose max)
🔴 RougeDépassement de la dose homologuée

Un tooltip au survol indique le pourcentage exact et la dose maximale autorisée.

2. AMM Expirée

Au chargement du dashboard, le catalogue est croisé avec la base e-phy :

  • Un badge rouge apparaît sur le bouton Catalogue si des produits ont une AMM retirée.
  • Un toast d'avertissement indique le nombre de produits concernés.

Cela permet de détecter si un produit que vous utilisez a été retiré du marché depuis votre dernière utilisation.

3. DAR (Délai Avant Récolte)

Après l'enregistrement d'une intervention phytosanitaire, un toast affiche la date limite de récolte pour chaque produit appliqué :

Exemple : "DAR : Roundup : DAR 7j (récolte après le 11/07/2026)"

Cette information est calculée automatiquement à partir de la date de l'intervention et du DAR renseigné dans le catalogue.

Bilans IFT et Registre Phyto

Calcul des Bilans IFT

  • Sélectionnez simplement une culture ainsi qu'une campagne de travail.
  • Le système gère nativement le chevauchement des cultures d'hiver (ex : blé, triticale, colza) en nommant les campagnes sous la forme 2025-2026.
  • Affiche les volumes d'intrants totaux, la surface cadastrale de l'îlot et l'Indicateur de Fréquence de Traitement (IFT) propre à chaque produit appliqué.
  • ⚠️ Conformément à la réglementation, la surface exploitée comme base de calcul pour l'IFT est strictement la surface cadastrale enregistrée pour la parcelle.

Export Registre Phyto XML

Génère un fichier de données structurées au format XML, répondant point par point au cahier des charges officiel du registre phytosanitaire :

  • Identité administrative et coordonnées de l'exploitation agricole.
  • Historique des interventions phytosanitaires : produit, dose unitaire, surface cadastrale réglementaire (qui prévaut sur la surface calculée par le tracé GPS Traccar), relevés météo certifiés et nom de l'opérateur ayant réalisé le traitement.

📤 Partage & Alertes automatiques (nouveauté v15.6)

Partage manuel (email / SMS / WhatsApp)

Un bouton 📤 Partager apparaît sur les points d'observation terrain, les parcelles (carte de chantier) et les fiches d'intervention (Carnet). Au clic, un petit menu propose le canal : ✉️ Email, 📱 SMS ou 💬 WhatsApp — l'application ouverte sur l'appareil se charge de l'envoi, aucune configuration serveur n'est nécessaire pour cette partie.

Depuis la liste des points d'observation, une case à cocher par point permet de sélectionner plusieurs points et de les envoyer en un seul message groupé.

Un modèle de message (en-tête et signature) personnalisable dans ⚙️ État système est automatiquement ajouté autour du contenu de chaque envoi.

Alertes email automatiques (SMTP)

Contrairement au partage manuel ci-dessus, ces alertes sont envoyées par le serveur lui-même, sans aucune action de l'utilisateur — nécessite de configurer un serveur SMTP (identifiants email) dans ⚙️ État système.

  • Traccar inaccessible : vérification automatique toutes les 5 minutes ; un email est envoyé uniquement lors du changement d'état (passage accessible → inaccessible, ou l'inverse), jamais à chaque vérification.
  • Point terrain sensible : un email est envoyé automatiquement dès qu'un point de catégorie "maladie/ravageur" ou "panne" est enregistré sur la carte de chantier.

Un bouton ✉️ Envoyer un test permet de vérifier la configuration SMTP avant de compter dessus.

🌦️ Prévisions météo

Le tableau de bord affiche désormais les prévisions à 4 jours, basées sur le modèle officiel Météo-France ARPEGE Europe (résolution ~11 km, via Open-Meteo). La position de référence de l'exploitation se configure dans ⚙️ État système.

📥 Export calendrier (.ics)

Le bouton 📥 .ics dans la modale Calendrier exporte les interventions détectées au format iCalendar standard, importable dans Google Calendar, Outlook ou Apple Calendar — pratique pour partager le planning avec un salarié qui suit son calendrier personnel plutôt que le dashboard directement.

Notes techniques & Maintenance

  • Migrations de base de données silencieuses : La structure de la base SQLite database.db s'auto-ajuste de manière transparente en tâche de fond. Aucune exécution de script SQL ou action humaine n'est requise lors du déploiement d'une mise à jour applicative.
  • Sécurité des accès : Votre mot de passe administrateur est haché avec PBKDF2-HMAC-SHA256 (100 000 itérations, sel aléatoire propre à chaque mot de passe) avant d'être sauvegardé dans le fichier password_override.txt — jamais stocké en clair. Un mot de passe déjà en place avant cette version est migré automatiquement au format haché dès la prochaine connexion réussie, sans action requise. (nouveauté v15.3)
  • Mot de passe perdu ou fichier corrompu (nouveauté v15.3) : supprimez password_override.txt sur le serveur et redémarrez l'application — le mot de passe repasse au mot de passe par défaut d'usine, à changer ensuite depuis "🔑 Mot de passe". Un fichier corrompu (écriture interrompue par une coupure serveur, par exemple) est détecté automatiquement au démarrage et provoque ce même repli, sans verrouiller l'accès administrateur.
  • Alerte mot de passe par défaut (nouveauté v15.3) : tant que le mot de passe d'installation n'a jamais été changé, un bandeau d'avertissement s'affiche en haut du dashboard, avec un lien direct vers "🔑 Mot de passe" — masquable pour la session en cours, mais réapparaît tant que le changement n'a pas réellement été fait.
  • Protection anti-bruteforce : 5 tentatives de connexion échouées depuis une même adresse IP déclenchent un blocage de 15 minutes. Le registre des tentatives est nettoyé automatiquement en arrière-plan (au plus une fois toutes les 5 minutes) pour ne pas accumuler indéfiniment les adresses IP inactives en mémoire.
  • Optimisation du réseau (Cache Traccar) : Le temps de conservation du cache des requêtes API Traccar est modifiable via l'interface afin d'éviter les requêtes superflues vers le serveur GPS et de garantir une fluidité parfaite.
  • Design Mobile-First : L'ensemble des tableaux, graphes et cartes bénéficie d'une interface responsive design fluide, optimisée pour le travail de terrain sur écrans tactiles de smartphones ou tablettes.
  • Politique de Sauvegarde (Backups) : Par mesure de sécurité, la base de données database.db est automatiquement dupliquée dans le répertoire backups/ lors de chaque démarrage du serveur, toutes les 24 heures à heure fixe via un thread d'arrière-plan, ou instantanément à la demande via l'action manuelle dédiée de l'interface (⚙️ État système → Sauvegarder).
